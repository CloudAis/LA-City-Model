# 阶段09：优化资源和本地交互查看器

本阶段使用已验收的阶段08工程及其既有真实地理数据。作者工程保留在 `scenes/stage08_city_medium.blend`，没有把实时合并网格写回原建筑、地形、道路或地标。最终验收状态、实测性能和已知限制分别见 `STATUS.md`、`outputs/stage09_city_medium_acceptance.json` 与 `docs/stage09_performance.md`。没有执行阶段10总验收。

## 启动与编辑

```bash
cd /workspace/Base
./viewer/start.sh --port 8090
```

在运行服务的机器上打开 `http://127.0.0.1:8090`。本机浏览构建产物只需Python3.10以上和支持WebGL2的浏览器，不需Node或Blender；云环境的127.0.0.1不等于用户电脑的127.0.0.1。将便携包解压到自己的电脑后，可运行其中 `python start.py`。没有使用CDN或远程底图瓦片。

查看器源码在 `viewer/src/`，生产构建在 `viewer/dist/`。修改源码后，在 `viewer` 执行 `npm ci`、`npm run build`。Node依赖由package-lock.json锁定：Three.js0.179.1、meshoptimizer1.3.0，开发构建使用TypeScript和Vite，版本以package-lock为准。生产JS包含必要解码器及WASM数据；MIT许可随构建附带。

`scenes/stage09_runtime_checkpoint.blend` 是从实际运行时资源解码、回载并保存的代表性检查场景，含真实城市坐标的街区/道路/地形及地标样本，不是重复保存一份全城最高细节工程。完整编辑结构仍在阶段08及两个链接源，完整实时城市在阶段09资源清单中。

## 操作

- 左键拖动环绕、滚轮缩放、右键平移；单击模型打开属性。
- 自由飞行：按住左键调整方向，W/A/S/D移动、Q/E升降、Shift加速。它是模型浏览用自由相机，没有建筑碰撞或行人导航系统。
- O环绕、F飞行、G概览、H说明、Esc关闭面板并回到环绕。
- Historic Core、Civic Center保留来源机位；地标搜索和列表定位十个真实区域，模型之间的地理距离不改变。
- 图层、四套光照、三档质量均可切换。来源与精度入口始终可见，技术统计在可选诊断面板。

## 模型组织和分块

`outputs/stage09/resources/manifest.json` 列出资源ID、所属图层、LOD、文件地址、字节数、SHA256、真实城市包围盒、局部原点、要素数量、属性包地址、来源与精度摘要及量化误差界。主要图层为terrain、roads、buildings、landmarks、vegetation、furniture、water。

地形和一般交通以既有1000m块为基础；普通建筑保留既有1000/250/125m来源单元，两个精修区按整栋建筑独立流送，使用来源父级原点。同一建筑的主体、屋顶、门窗和所有LOD使用同一归属，跨块整体对象不重复生成。地标独立管理。相邻地形使用原有边界样本，运行时简化保留原始2m外边界三角带；量化的额外差异单列，不将计算误差称为源测量精度。

合并以图层、分块和有效材质为界，保留每顶点 `_FEATURE_ID_0`。命中三角形后读取对应属性包，映射到源UID；该绘制索引与外部稳定UID分开。建筑庭院和分部沿用来源几何。原有普通代理的替换ID从一般层排除，精修建筑和十个地标分别加载，避免双主体。

同材质的完全相同顶点按位置、法线、UV、切线、颜色和要素ID联合去重，并保留首次使用的空间顺序。每个被索引的属性都实际逆映射比较，不能仅按坐标合并不同建筑或UV边界。Meshopt在规定量化之后逐缓冲区编码、解码并比较；索引使用INDICES模式保留原序列。压缩对比保留原始GLB、gzip和Meshopt的实际字节数及真实浏览器样本，不将预测压缩率当作测量。

重复树木和街道设施使用实际原型与来源点位的InstancedMesh，保留实例来源ID。没有凭空为整城填充树木。

## 实际LOD和材质取舍

完整近景为LOD0；中间立面保留来源墙体开口、玻璃、入口、屋顶和主要轮廓，省略细窗框/微小设备。一般建筑LOD1覆盖保留的来源建筑；远景LOD2只选取部分高层建筑以控制开销。全市概览LOD3包含实际地形、来源较高建筑和独立地标，省略大量低层体量；放大后加载本地完整建筑。远景主要道路用来源中心线的1px线显示，它是示意性的运行时LOD，不冒充真实道路宽度；靠近后使用原路面、桥隧和道路断面。

全市概览的道路线作为地图叠加层关闭深度测试，避免被简化地形遮挡；来源线坐标未抬高或移动。该规则仅用于概览线，近景实体道路照常参与深度测试和遮挡。

低/中档使用Base Color与简化漫反射照明，停用法线/ORM采样和物理透射来适配本次软件渲染环境；完整PBR贴图与透射仍保存在GLB，高档实际使用。编辑材质和原始纹理保留在阶段08。运行时颜色、曲面面法线及天空与Cycles并不逐像素相同，不能把实时兼容版本描述成完整离线光传输。夜景保留源场景固定分布的发光构件，浏览器不复现所有离线投光灯与间接光。

近景相机所在道路与地形块先于立面细节分配预算。预算不足时先选择能够容纳的相邻简化LOD，避免直接退到省略支路的远景道路。来源交通薄面中存在向下的三角形绕序；Blender原先双面显示，运行时GLB明确使用双面材质保持道路可见，未改变其位置或原始索引。实际街景射线检查确认道路存在，修复前候选图保留在历史目录，不计最终验收。

## 坐标与相机

工作坐标EPSG:32611，原点UTM为(384992.75594820484,3767182.3649733574)，城市坐标X向网格东、Y向网格北、Z向上，米制。地面高程轴为NAVD88；未知源建筑ELEV没有作为同基准绝对海拔加入。

城市到glTF仅转换一次：`(x,y,z) → (x,z,-y)`。资源内部局部原点与城市位置保存在清单，浏览器以双精度保存全局位置，并在相机离局部原点约2000m时按1000m整格重置渲染原点。没有把UTM的数百万米直接写入GPU顶点。概览资源使用独立更粗的量化界；近景量化界不能推导为数据的测绘精度。

近远裁剪面按概览/近景调整；近景0.12m、远景按范围控制。中档省略远处密集标线/细路缘，减少小偏移叠面的深度冲突。指南针使用Downtown参考点收敛角−0.697480°换算参考真北；比例尺是焦点平面上的透视近似。空间验证报告分别记录实际模型位置、轴向计算和来源本身的精度边界。

## 加载、错误和释放

距离分级加15%滞后，配合视锥筛选和小范围邻块预取；Three.js继续按对象剔除。根据当前档位限制可见资源与三角形；被定位的地标优先。请求通过AbortController取消，失败最多重试2次并显示可重试的错误。

缓存按几何缓冲字节和最后使用时间管理；离开区域后释放几何、材质、纹理和ImageBitmap。共享纹理按实际材质槽引用计数，重复实例共享几何。属性包缓存最多8份，道路按每1000个源要素拆包，避免选择一栋建筑时加载全市道路属性。内容哈希命名的PNG允许本地HTTP缓存；GLB由应用缓存控制。WebGL解码/图片操作已开始后不能保证立刻终止，结果会在失效后释放。

固定巡游路径为概览→Historic Core→Civic Center→Griffith Observatory→U.S. Bank Tower→概览，36秒一轮，含停留与抬高的平滑相机转场。测试实际重复三轮，检查相同阶段资源数、缓存、浏览器内存和最终释放；FPS统计是实际测试浏览器的渲染循环结果，没有物理显示器刷新或硬件GPU的达标声明。
